## Key Idea

ECMP spreads flows randomly across a fat-tree's paths. That's great in aggregate, but a host can't reliably move one flow off, say, a switch quietly dropping packets. The usual trick is to re-hash and hope, which can land you on the same bad path again and again. P-ECMP borrows a feature commodity switches already have, ECMP groups. A selector in the header (DSCP in Tencent's deployment) picks a row of a compiled table, so the host gets a predictable path offset or an exact next hop. Unmarked traffic just keeps using plain ECMP.

## Critique

I found this pretty convincing. It needs no new hardware, it's already doing failover in production, and rerouting works on the first try every time. Random re-pathing, by contrast, has a 95th percentile over 4.5 seconds after a top-of-rack failure. The catches: you need dual-homed servers for the full benefit, exact-next-hop control needs up to 24 selector bits (DSCP only has 6) plus topology knowledge on hosts, and most use cases are only simulated.
